## 黒い画面、ちょっと身構えませんか

ターミナル、正直あまり得意ではありません。開くことはできます。コマンドも調べれば出てきます。それでも、できれば開かずに済ませたい。同じ気持ちの方、けっこういるんじゃないでしょうか。

私が毎日使っている MulmoTerminal と MulmoClaude も、立ち上げるときだけはターミナルの出番です。

ここで「ターミナルが苦手なのに MulmoTerminal を使うのか」と思われたかもしれません。実は逆で、この2つはどちらも黒い画面と向き合う時間を減らすためのツールです。MulmoTerminal は名前こそターミナルですが、実際に触るのはブラウザの画面。コマンドを打ち込む代わりに、AI に日本語で頼んで、進み具合を眺めます。MulmoClaude にいたっては、プログラミング知識がなくても使えることを掲げています。

苦手な人ほど恩恵がある側のツールなのに、**立ち上げるときだけターミナルが残っている。**

「そこも AI に頼めばいいのでは」とも思いました。実際、Claude Code に「MulmoTerminal を起動して」と言えば立ち上げてくれます。ただ、これはこれでもったいない。サブスクでも使える量には上限がありますし、会話の文脈も消費します。何より、起動のたびに頼むこと自体が面倒です。自分で秒で終わることは秒で終わらせて、AI は AI にしかできないことに使いたい。

とにかく楽をしたいんです。押したら開く。それだけでいい。

そこで、押したら開くボタンを作りました。

![メニューバーから開くまで](/images/mulmo-control/mulmo-control-demo.gif)
*これだけです。メニューバーのアイコンを押して、「開く」*

## Mulmo ファミリーの紹介

先に立場を書いておきます。私は Singularity Society という、エンジニアや起業家が集まるコミュニティの BootCamp（第4期）に参加しています。エンジニアではありませんが、そこで1年かけて自分のアプリを作る、という枠に混ぜてもらっています。この記事に出てくる Mulmo 系のツールは、いずれもそのコミュニティから生まれたものです。

その Mulmo という名字のツールが、いま何人もいます。それぞれ担当が違います。

- **MulmoTerminal** — Claude Code をブラウザから使う。複数のセッションを1画面で並列に走らせる
- **MulmoClaude** — 自分だけの AI アシスタントを育てる。記憶もデータも自分専用アプリも、全部自分のコンピュータの中に貯まる
- **MulmoCast** — AI と一緒にプレゼンを作る。MulmoScript という中間言語から、動画・ポッドキャスト・スライド・PDF に書き出す
- **MulmoCast Vision** — スライド生成担当
- **MulmoBridge CLI / Slack Bridge** — ターミナルや Slack から MulmoClaude に話しかける通り道

この記事は、ここに非公式の新入りを1人足しました、という話です。名前は Mulmo Control。担当は残りの家族を起こして回ること、それだけです。

## 本家がすごい

ブラウザから Claude Code を使える、と書きましたが、本領はここからです。

- Claude Code のセッションをグリッドに何枚も並べて同時に走らせる（Claude だけでなく Codex やシェルのセルも並ぶ）
- 作業が一段落するとスマホに通知が来る
- そのままスマホから返事ができる。yes / no / continue はタップ1つ
- 導入は `npx` コマンド1発。Electron も設定ファイルも無し

公式 README の言い方を借りると "walk away, get pinged, jump back in"。AI に仕事を任せて散歩に出て、信号待ちでスマホに届いた「どうしますか？」にタップで返す、ができます。

MulmoClaude のほうは「自分だけの AI アシスタントは買えない、育てるしかない」を掲げたツール。プログラミング知識なしで「こういうのが欲しい」と言えば、自分ひとりのための小さなアプリを作ってくれます。

この2つが、AI に作業を任せる日常の置き場所になっています。

![MulmoTerminal のヘッダー](/images/mulmo-control/mulmoterminal-header.png)
*ヘッダーの右側に、Claude をどれくらい使ったかが出ます。この日は5時間あたり48%、7日間で81%*

そして、更新が異常に速い。npm の公開履歴を数えると、こうなっていました（2026年8月8日時点）。

- **MulmoTerminal**: 直近30日で 57回、直近7日だけで 16回。初版 0.1.0 が6月17日なので、51日で 4.7 系まで来ている
- **MulmoClaude**: 直近30日で 18回、直近7日で3回。最新は 1.12.0

2つ合わせてひと月に75回。先週まで無かった機能が今週ある、という速さです。

理由は2つあると思っています。ひとつは、使っている人の声を見てすぐ直してくれること。Issue と PR の通し番号は、初版から51日で1500番台に届いています。もうひとつは、MulmoTerminal を使って MulmoTerminal を作っていること。開発者の方の記事が面白いので、ぜひ。1日のコミット数が500を超えた話です。

https://zenn.dev/singularity/articles/diy-terminal-500-commits

その記事自体も MulmoTerminal の中で書かれていて、裏のセルで別のプログラムを書かせながら、片手間に原稿も書かせている、とあります。自分の道具で自分の道具を良くしていく速度が、そのままリリース数に出ているのだと思います。

ただ、追いかけるにはまず「新しい版が出た」と気づかないといけません。一度立ち上げっぱなしにすると、そこで時間が止まります。

## 作ったもの

起動と、更新に気づくこと。この2つだけを肩代わりする macOS アプリを作りました。名字は勝手に借りたので、あくまで非公式です。

https://github.com/shoujiki-panman/mulmo-control

できることは4つです。

- **開く** — MulmoTerminal / MulmoClaude が起動していなければ起動してから、ブラウザで開く
- **ログイン時起動と自動復帰** — MulmoTerminal をログイン時に起動し、落ちたら戻す
- **更新の見張り** — 本体・周辺ツール・アプリ自身の最新版を定期チェックし、更新があるとアイコンが変わる。更新後は公式 Changelog から新機能の要約を出す
- **周辺ツールの追加** — MulmoCast などのインストール

覚えることは「開く」だけです。タブを閉じても、Mac を再起動しても、1クリックで戻ってこられる。放っておいても、新しい版が出ればアイコンが教えてくれる。

インストールはターミナルに3行貼るだけです（ここは正直、まだターミナルが要ります。後述）。

```bash
git clone https://github.com/shoujiki-panman/mulmo-control.git
cd mulmo-control
./install.sh
```

必要なのは macOS 14 以降と Node.js だけ。ふつうは Xcode も要りません（ビルド済みのアプリを Releases から取ってくるため。取れなかったときだけ手元でビルドします）。macOS の版か npm が足りなければ、何も書き込む前に日本語で理由を出して止まります。MulmoClaude は無くても入ります。見つからなければそう伝えたうえで続行し、MulmoTerminal だけで使える状態になります。

最後に `Installed: /Applications/Mulmo Control.app` と出れば完了です。

### 開いても、ウィンドウは出ません

ここが分かりにくいところなので、先に書いておきます。**アプリを開いても、ウィンドウは出ません。** 画面右上のメニューバーに、ターミナルの形をした `>_` アイコンが増えるだけです。メニューバーの項目が多い Mac やノッチ付きの Mac では、表示しきれずに隠れていることもあります。

![メニューバーのアイコン](/images/mulmo-control/menubar-icon.png)
*いちばん左の丸いアイコンがそれです。更新があるとこの下向き矢印に変わります*

初回は macOS が「ログイン項目と機能拡張」の確認を出すことがあります。常駐して MulmoTerminal を起こす役なので、許可して大丈夫です。

![Mulmo Control の操作画面](/images/mulmo-control/panel.png =360x)
*上から順に、更新の有無、MulmoTerminal、MulmoClaude、追加ツール*

画面は3つのタブに分かれています。普段使うのは「運用」だけで、開く・再起動・停止・ログの4つです。常駐のオン・オフもここで切り替わり、設定画面を探す必要はありません。インストールしただけでは常駐せず、一度「開く」を押した時点からログイン時の自動起動と自動復帰が有効になります（「停止」で両方とも解除）。残りは、周辺ツールを入れる「追加」と、インストール状態と最新版が並ぶ「環境」です。

更新があると、メニューバーのアイコンがターミナル型（`terminal.fill`）から下向き矢印（`arrow.down.circle.fill`）に変わります。macOS の通知でも「Mulmo の更新があります」と届くので、メニューバーを見ていなくても気づけます。日常の使い心地としては、ここが一番効いています。

なお、MulmoClaude には公式のアイコン起動があります（`npx mulmoclaude@latest create-shortcut`）。このアプリが足しているのはその先で、2つをひとつの場所から扱えること、落ちたら勝手に戻ること、更新を見張ることです。

## ブックマークは、当てにならない

この手のツールはブラウザで開くので、私はブックマークしていました。ところが、これが意外と当てになりません。

ブックマークが指しているのは `http://localhost:5173` のような「場所」であって、アプリそのものではないからです。そこにアプリがいるかは、その時々で変わります。

- サーバーが動いていなければ、誰もいない
- 既定ポートが埋まっていると、MulmoTerminal は「空きポートで2つ目を起動していいか」を聞いてくる。`--port` を指定していたり、聞ける端末が無い場合は起動を中止する
- 起動方法でも変わる。MulmoClaude は launcher 経由なら `localhost:3001`、`yarn dev` なら `localhost:5173`
- `5173` は Vite の既定ポート。別プロジェクトの開発サーバーと取り合う

私が踏んだのは最後のパターンでした。`localhost` は `::1`（IPv6）と `127.0.0.1`（IPv4）の両方に解決されます。そして**別々のプロセスが、同じ 5173 番を IPv6 側と IPv4 側で1つずつ掴めてしまう。**

```
node 46845  TCP [::1]:5173 (LISTEN)       ← 別プロジェクトの開発サーバー
node 98574  TCP 127.0.0.1:5173 (LISTEN)   ← MulmoClaude
```

ブラウザは `::1` を先に引くので、前者に当たって 404。厄介なのは、`curl http://localhost:5173/` だと IPv4 に落ちて 200 が返ることです。「curl は通るのにブラウザだけ 404」という、いちばん疑いにくい状態になります。切り分けは `127.0.0.1` と `[::1]` を両方叩くこと。違えば居座り確定です。

つまりブックマークは「アプリへのリンク」ではなく「住所のメモ」です。引っ越していたら空振りするし、別の住人がいたら知らない部屋に入ってしまう。不具合ではなく、ブラウザで動かすツールなら当たり前に起きることです。

メニューバーのアプリは、ここを引き受けます。住所を覚えるのは、人間ではなくアプリの仕事にしました。

## 中身

Swift のファイル1枚（1,800行ほど）です。作ってみて「なるほど」と思った4つを書いておきます。

**ウィンドウを出さない** — メニューバーだけに住むアプリにするには、`Info.plist` に `LSUIElement` を書きます。これ1行で、Dock にも出ず、ウィンドウも持たないアプリになります。実装ではなく宣言で決まるのが意外でした。

**ログインしたら勝手に起動して、落ちても戻る** — macOS には launchd という常駐の面倒を見る仕組みがあり、設定ファイルを1つ置くと「ログイン時に起動」と「落ちたら再起動」をやってくれます。ただし置くだけでは有効にならず、登録した時点から動き始めます。なお「落ちたら再起動」を無条件にすると、起動に失敗し続けるプロセスを永久に蘇生させます。これで実際に事故を起こしました（後述）。

**Intel の Mac でも動かす** — いまの Mac は Apple Silicon と Intel の2種類があります。それぞれ向けに1回ずつビルドして、`lipo` というコマンドで1つのファイルに束ねると、どちらでも動くアプリになります。やることはこれだけです。

**署名していないアプリを配る** — ブラウザでダウンロードしたファイルには、macOS が「これは外から来た」という印を付けます。この印があると「開発元を確認できません」と言われて開けません。そこでインストーラの中で、印の付かない方法（`curl`）で取得し、念のため印を消し、自分で署名し直しています。Apple の正式な署名は有料なので、そこは通っていません。

## 配って30分で、洗礼を受けた

BootCamp の Slack に紹介動画つきで流したところ、30分で最初の利用者からこう返ってきました。

> さっそくインストールしてみたのですが、起動できないですね。
> 何もメッセージは出ません

自分の Mac では一度も見たことのない状態でした。当然で、私の Mac には Node.js も Xcode も対象のツールも、もう全部そろっています。インストーラが通る道は、すでに舗装済みでした。

そこで、まっさらな Mac のふりをさせて動かしてみました。空のフォルダを1つ作り、そこを「自分の家（ホームディレクトリ）」だと思い込ませて実行します。

```bash
mkdir -p /tmp/cleanroom/home
env HOME=/tmp/cleanroom/home ./install.sh
```

これでインストーラから見える世界が、何も入っていない Mac と同じになります。ただし `/Applications` だけは `HOME` と無関係な絶対パスなので、そのまま走らせると本物のアプリを消して置き換えてしまいます。実際には、その行だけテスト用の場所に書き換えたコピーを走らせました。「Xcode が入っていない Mac」も同じ発想で、必ず失敗する偽物のコマンドを本物より先に見つかる場所に置いて再現しました。

同じ症状が出ました。当時のインストーラはその場で Swift をビルドする作りで、Xcode Command Line Tools が無い Mac ではエラー1行だけ出して死にます。しかもその1行が npm の長いログに埋もれて、「何もメッセージが出ない」ように見えていました。

直したのはこの3つです。

- インストーラの先頭で macOS の版と npm を確認して、足りなければ1つもファイルを書かずに日本語で理由を言って止まる
- 既定をビルドからダウンロードに変更。ビルド済みアプリを GitHub Releases に置き、Apple Silicon と Intel の両対応バイナリを `lipo` で束ねた。取れなかったときだけ手元ビルドに落ちる。これでふつうは Xcode が要らなくなった
- README のインストール手順のすぐ後に「メニューバーにしか出ません」を太字で書いた

1つ目は、こうなりました。

![足りないものは日本語で伝えて止まる](/images/mulmo-control/install-guard.gif)
*上は Node.js が無い Mac、下は macOS が古い Mac で `./install.sh` を実行したところ*

ただ、振り返ると、最後に残っていたのは「アプリがどこにあるか分からない」という話でした。作った本人は、どこに置いたかも、どこに出てくるかも知っています。だから「インストールが終わったら、あとは開くだけ」としか思わない。でも初めて入れた人には、それがどこにあるのか分からない。私はそこに説明が要ることに、言われるまで気づけませんでした。

一度自分のために作ったものが人の手に渡って、そこで初めて、人のために考え始めた気がします。恥ずかしい話ですが、それまでは考えていなかったんだと思います。

## そして3日で7回直した

ここまでが最初の日の話です。そのあとどうなったかというと、**3日間で7回リリースしました。**

| 版 | 直したこと | 誰が見つけたか |
|---|---|---|
| 1.0.2 | 更新が途中で止まる | 利用者 |
| 1.0.3 | 更新に失敗しても「更新しました」と出る | 利用者 |
| 1.0.4 | Claude のログイン切れに気づけない | 自分 |
| 1.0.5 | 新機能の要約がずっと出ていなかった | 自分 |
| 1.0.6 | スマホ連携が切れても分からない | 自分 |
| 1.0.7 | スマホ連携が繋がらない | 自分 |
| 1.0.8 | 画面がリロードし続ける | 利用者 |

7本のうち3本は、使ってくれた人の報告から出ています。残りも、自分が「使う側」に回ったときに踏んだものでした。機能そのもののバグは、この間1件も出ていません。出たのは全部、入口と、使い続ける途中です。

### 嘘をつくアプリになっていた

「一括更新しました」と表示したのに、更新ありのバッジが消えない、という報告がありました。

調べたら、報告の作り方が間違っていました。更新を走らせる前に、「これから上がるはずのバージョン」で報告文を組み立てていたんです。だから失敗しても成功として出る。しかも失敗した場合は報告ごと捨てる作りだったので、一部だけ失敗すると、成功した分まで無かったことになる。

更新の前後でバージョンを実測して、その差で報告するように変えました。いまは「一部だけ更新しました」と出て、動かなかったものには「1.8.0 のまま」と現状を書きます。

**自分が書いたコードが利用者に嘘をついていた**、というのが、この修正で一番こたえたところです。

### 利用者からの調査報告

いちばん驚いたのは最後の1本です。「朝起きたら MulmoClaude の画面が1秒おきにリロードし続けていた」という報告に、**原因の連鎖が7段階まで書かれていました。**

要約するとこうです。私のアプリが入れる常駐設定が「落ちたら再起動」を無条件にしていて、ポートが埋まっていると起動に失敗し、それを異常終了とみなして10秒ごとに永久に再試行する。しかも失敗する側のプロセスも、ポートを掴む前にファイルを書き換えるので、そのたびに画面がリロードされる。

自分でも全部裏を取りました。正しかったです。しかも「対策は2つあり、片方だけでは止まらない」という指摘まで正確でした。自分の環境では起きていませんでしたが、ログを見たら同じ衝突が5回記録されていました。踏むのは時間の問題だったということです。

### 3日で分かったこと

**入口のバグは、作った本人には一生見えません。** この3日間で見つかったものは、どれも私が何十回も通った道にありました。それでも見えなかった。

見えるようになったのは、他人が通ったからです。しかも、ただ「動きません」と言われるのではなく、画面のスクリーンショットや、ログや、原因の推測まで添えて返ってきました。

## 着想は、他の人のツールから来ている

このアプリの形は、自分で思いついたものではありません。着想元が2つあります。

ひとつは [Capsomnia](https://www.producthunt.com/products/capsomnia)。Caps Lock キーを「MacBook を眠らせないための物理スイッチ」に変えるアプリです。オンにすれば蓋を閉じても Mac は起きたままなので、AI に頼んだ作業が途中で止まらない。機能はこれ一つですが、AI に長い作業を任せる人なら誰もが踏む場所に、ぴったりはまっています。

もうひとつは、Claude Code や Codex の使用量をメニューバーに出すツール。私は CodexBar を使っています。あと何回使えるのか分からないまま作業するのは落ち着かない、というだけの話ですが、あるとないとでは違います。

どちらも、AI を使っている自分たちの中から出てきた「こういうのがあったらいいな」を、そのまま形にしています。私はこの2つを、入れてから一度も外していません。この2つを自分の Mac に入れて使っていたから、「メニューバーに住んで、起動と更新の面倒を見る」という形が、自分の困りごとと結びつきました。眺めているだけでは、たぶん繋がらなかったと思います。

AI まわりのツールは毎日たくさん出てきます。実際に触って、作って、直してを繰り返していると、あるとき見たものと自分の困りごとが急に繋がる。もし身近に「ちょっとこうだったらいいな」があったら、そこから作ってみてください。すごいものでなくていい、と思えたおかげで、私はひとつ作りきれました。

## 見てくれる人がいる場所

作ったら、誰かに見てもらうところまでやったほうがいいと思います。X でも Zenn でもいい。ただ、返事が返ってくるのは、時間をかけてフィードバックしてくれる人がいる場所です。

個人的なツールは、会社では話しにくい。仕事と関係ないし、相手の時間をもらってまで見てもらうものでもない。かといって、ただ公開しただけでは、たいてい何も返ってきません。

私は一人だと続きませんでした。動画つきで流したら「さっそく入れてみた」と返ってきて、つまずいた内容まで書いてもらえた。それがあったから、その日のうちに直す気になりました。3日で7回直せたのは、その間ずっと誰かが見てくれていたからです。

同じコミュニティで、bull さんも似たことを書かれています。あちらは参加者の一言から機能が生まれた話、こちらは入口が壊れていた話でした。内側から見えないものが違うだけで、起きていることは同じだと思います。

https://zenn.dev/bull/articles/singularity-society-feedback-loop

BootCamp はエンジニアでなくても参加できて、オンラインなのでどこからでも入れます。作りたいものがある方は、のぞいてみてください。

https://singularitysociety.org/

## これから

ひとつ、自分でも笑ってしまう矛盾が残っています。

**ターミナルを開きたくない人のための道具なのに、入れるときだけターミナルが要る。**

冒頭のあの3行です。git clone して、cd して、install.sh を叩く。ここを消さないと、いちばん届けたい人に届きません。目指しているのは、Releases から zip を落として Applications に放り込んで終わり。

そしてこの3日で、もう1つ課題が増えました。直した7本のうち4本は、入れたあとに起きたものです。ログインが切れる、更新が失敗する、連携が切れる。どれも「入れるとき」ではなく「使い続ける途中」で詰まりました。

なので、いまは目標を2つに分けています。

- **入れるのにターミナルが要らない**（zip をドラッグするだけ）
- **使い続けるのにターミナルが要らない**（詰まったとき、何が起きているかがメニューバーで分かる）

後者は、この3日間が教えてくれたものです。Issue を並べて、1つずつ潰しています。

https://github.com/shoujiki-panman/mulmo-control/issues

ターミナルに慣れている人には、このアプリは要らないかもしれません。`npx` 1発で足りるので。狙っているのはその手前、コマンドを覚えるより先に中身を触ってみたい人の、最初の一段です。動いているところは[リポジトリの README](https://github.com/shoujiki-panman/mulmo-control) に1分半の紹介動画を置いてあります。

最後に、本体から触ってみたい人へ。MulmoTerminal には、しっかりした日本語ガイドがあります。ターミナルの開き方から、Node.js・Claude Code・git / gh の入れ方（Mac / Windows 両方）、起動コマンド、つまずいたときの対処まで、1ページにまとまっています。この記事でずっと「関門だ」と書いてきた場所が、最初の一歩から順に案内されています。触ってみると本当に便利なので、まずは本体から、という人はこちらからどうぞ。

https://receptron.github.io/mulmoterminal/guide/ja/

## 本記事について

Claude Codeの最初のモデルはOpus 5.5です。いつも上位のモデルでいいのか、もっと速く安く済ませられないのか。迷ったことはありませんか。

9月28日、Anthropicは「Claude Sonnet 5.5」を出しました。前のSonnet 5より30%以上速く、作業あたりの費用は最大30%下がり、成績は上位のOpus 5.5に迫っています。

![Sonnet 5.5とOpus 5.5の使い分け](/images/claude-sonnet-5-5-or-opus/which.png)
*使い分けの目安（発表の説明をもとに筆者作成）*

この記事は、発表と開発者向けの説明をClaudeに読んでもらい、数字を比べたものです。ClaudeをClaude CodeやAPIで使っていて、モデル選びで迷っている方向けです。

## 概要

| 項目 | Sonnet 5.5 | Opus 5.5 |
|---|---|---|
| 向いている仕事 | やることがはっきりした日々の作業 | 答えの決まっていない複雑な仕事 |
| 料金（100万トークンあたり、入力／出力） | 2ドル／10ドル | 4ドル／20ドル |
| 速さ | 速い（Sonnet 5より30%以上） | 中くらい |
| 一度に読める量 | 100万トークン | 100万トークン |
| Claude Codeでの扱い | `/model sonnet`で切り替える | 最初から使われる |

## 構成

## 1. 料金はそのまま、使う量が減った

![料金の比較](/images/claude-sonnet-5-5-or-opus/price.png)
*料金表の値段は、Opus 5.5の半分*

Sonnet 5.5の料金はSonnet 5と同じです。入力100万トークンあたり2ドル、出力10ドルで、Opus 5.5の半分にあたります。トークンは、AIが文章を数える単位です。

値段が同じでも、作業あたりの費用は下がりました。1つの作業で使うトークンが、ずっと少なくなったからです。

![使ったトークンの比較](/images/claude-sonnet-5-5-or-opus/tokens.png)
*Balyasny Asset Managementの結果。1回答あたりのトークンが約4分の1に*

### ポイント

- 投資会社のBalyasny Asset Managementが金融の作業2,441件で試したところ、1回答あたりのトークンは約12万1千でした。Sonnet 5は約49万7千です
- 文章を書き出す速さは、Sonnet 5より30%以上上がりました。これまでのSonnetでいちばん速い、とされています

## 2. 成績はOpus 5.5に迫る

![試験の点数](/images/claude-sonnet-5-5-or-opus/scores.png)
*Anthropicが公表した試験の点数。高いほどよい*

| 試験の中身 | Sonnet 5.5 | Sonnet 5 | Opus 5.5 |
|---|---|---|---|
| コマンド操作を伴うプログラミング（Terminal-Bench 4.0） | 70.6% | 10.3% | 66.4% |
| あいまいな依頼で複数のファイルを直す（CursorBench 4.0） | 55.5% | 34.1% | 57.8% |
| 44の職種の実務（GDPval-AA v2.1、点数） | 1844 | 1449 | 1846 |
| パソコンの画面操作（OSWorld 2.1） | 80.1% | 57.0% | 81.8% |
| グラフの読み取り（Chartography） | 61.6% | 15.6% | 64.4% |

### ポイント

- Sonnet 5からは大きく伸び、Opus 5.5とは多くの試験で数ポイント差です
- コマンド操作を伴うプログラミングでは、Opus 5.5を上回りました。この試験のOpus 5.5の点は、考える深さを大きく上げた「Xhigh」の設定での値です
- スクリーンショットだけを見てゲーム「ポケットモンスター 赤」をクリアした、初めてのSonnetだそうです

## 3. 試した会社の結果

| 会社 | 結果 |
|---|---|
| Base44（アプリを作るサービス） | 実際のアプリ作り118件で、出来はOpus 5と同じ。完成までのやり直しは平均3.6回（Opus 5は7.7回） |
| Zendesk（問い合わせ対応） | 実際の問い合わせ数百件で、処理が20%速くなった |
| Box（ファイル共有） | 正確さが上がり、2.4倍速く、使うトークンは12%減った |
| Anthropic社内 | 決算資料から作らせた10枚の報告を、専門家2人が「このまま送れる」と判断 |

## 4. 使い分け

### Sonnet 5.5に向いていること

やることがはっきりした日々の作業です。バグの修正や、文書・スライド・表づくり、デザインの手直しが当てはまります。速いので、簡単な作業を何度もやり取りして詰めていく使い方にも向いている、と発表にはあります。

### Opus 5.5に向いていること

答えの決まっていない複雑な仕事や、判断を長く積み重ねる作業です。全体の設計を決めるような場面も、こちらに向いています。

### ポイント

- 考える深さを最大にすると、Sonnet 5.5もいくつかの試験でOpus 5.5に並びます。それでも、長く判断を続ける仕事ではOpus 5.5がはっきり上、というのがAnthropicの見方です
- 組み合わせる使い方もあります。ゲーム作りに使った人からは「Opus 5.5が設計を決めるなら、実装はSonnet 5.5に任せられる」という声が出ています

## 5. 切り替え方

### Claude Code

```
/model sonnet
```

### API

モデル名は`claude-sonnet-5-5`です。

考える深さの初期設定は、Claude Codeとアプリでは「Medium」、APIでは「High」です。一度に書き出せる量は12万8千トークンで、提供の終了は早くても2027年9月28日以降とされています。

## 6. 安全面

危険度の高いサイバーセキュリティの依頼は、利用者にも分かる形でSonnet 5に切り替えて答えます。ふだんのバグ探しや修正は、そのままSonnet 5.5の担当です。

Claudeの考えの中身を抜き出す行為を防ぐ仕組みも、Sonnetでは初めて入りました。そのため、会話を別のアカウントに移すことに制限がかかります。Claude Codeで作業の途中にアカウントを切り替える場合も対象です。

Anthropicは約1,850の場面で振る舞いを調べ、利用者の意図に反する目標を追う証拠は見つからなかった、としています。

## 使い分けの目安

| やりたいこと | おすすめ |
|---|---|
| 毎日のバグ直し、資料づくり | Sonnet 5.5 |
| 費用と待ち時間を減らしたい | Sonnet 5.5 |
| 新しいサービスの設計、答えの決まっていない調査 | Opus 5.5 |
| 設計から実装まで通して頼みたい | 設計はOpus 5.5、実装はSonnet 5.5 |

## 宣伝：続きを別のモデルに渡すならsession-relay

session-relayは、新しいチャットに「続きから」と打つだけで、前の会話を引き継ぐ道具です。新しいAIが前の会話を自分で読みに行き、続きから始めます。9月の更新で、続きを渡すAIの種類（モデル）を指定できるようになりました。

入れ方は、ターミナルで次の2行です。

```
npm install -g @shoujiki-panman/session-relay
relay install
```

詳しくは[前に書いた記事](https://zenn.dev/shoujiki_panman/articles/session-relay-no-handoff)にまとめています。

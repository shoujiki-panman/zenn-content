## 本記事について

Claudeデスクトップアプリの Code タブ（Claude Code）で、セッション（会話）が180件たまっていました。題名の多くは「きた」「次」「続きから」「これなんすか」です。どれが何の会話か、題名からは分かりませんでした。

この記事は、それを1回の会話で片付けた記録です。作業はすべてClaudeに頼んでやってもらいました。最後に、新しいセッションでも同じ状態が続くようにした仕掛けを公開しています。

Claude Code を毎日使っていて、サイドバーのセッションが増えすぎた方向けです。

![整理前と整理後のサイドバーの模式図](/images/claude-code-session-titles/sidebar-before-after.png)
*整理前と整理後（模式図。題名は実際に付け直したもので、プロジェクト名だけ伏せています）*

## 概要

やったことは5つです。

| やったこと | 手段 | その後も自動で続くか |
|---|---|---|
| 古いセッションを片付ける | アーカイブ | いいえ（ときどき頼む） |
| 題名を中身で付け直す | Claudeが会話を読んで付け直す | はい |
| 最後に触ったものを上に出す | サイドバーの表示を切り替える | はい（切り替えたまま） |
| 今やるものを目立たせる | ピン留め＋題名に「次＝」 | はい |
| 新しいセッションにも効かせる | 依頼のたびに動く仕掛け（フック） | はい |

## 構成

1. 古いセッションをアーカイブする
2. 中身を読ませて題名を付け直す
3. 並びは「日付で区切る・最近動いた順」にする
4. ピンは「今やるもの」、題名に「次＝」を入れる
5. 新しいセッションにはフックで効かせる

## 題名が最初の一言のまま残っていた理由

アプリはセッションの題名を自動で付けます。私の場合、その題名は最初に打った一言をほぼそのまま使ったものでした。「これどう？」とURLを貼って始めた会話は、あとから見ても何の話か分かりません。

もうひとつの原因は作業フォルダです。180件のほとんどが、同じ1つのフォルダで始まっていました。サイドバーには作業フォルダごとに分ける表示もありますが、フォルダが1つなら全部が1つの塊になります。

題名でもフォルダでも見分けられない。ここが出発点でした。

## 1. 古いセッションをアーカイブする

### アーカイブとは

サイドバーから外して、しまっておくことです。削除ではありません。アーカイブ済みの一覧から、いつでも戻せます。

### 頼み方

```
> 2週間より前のセッションをアーカイブして。作業が途中のものは残して
```

### ポイント

- 基準は日付だけにしました。1件ずつ要る・要らないを考えると終わりません
- 作業が途中のセッションは残します。続きをするとき困るからです
- 私の場合は180件のうち140件が片付き、残りは40件になりました

## 2. 中身を読ませて題名を付け直す

### デスクトップアプリのClaudeができること

デスクトップアプリのClaudeは、セッションそのものを扱えます。私の環境でできたのは次のことです。

| できること | 使った場面 |
|---|---|
| セッションの一覧を見る | 何件あるか、いつ動いたか |
| ほかのセッションの会話を読む | 題名では分からないものの中身 |
| 題名を変える | 「プロジェクト名：中身」への付け直し |
| ピン留めする・外す | 今やるものの印 |
| アーカイブする | 古いものの片付け |
| サイドバーの表示を変える | 日付で区切る表示への切り替え |

### 頼み方

```
> 残ったセッションの題名を、会話の中身を読んで「プロジェクト名：中身」に付け直して
```

### 付け直した例

プロジェクト名は伏せています。

| 元の題名 | 付け直した題名 |
|---|---|
| きた | 発信：ラベル確認ページとおすすめの仕組み |
| 次 | ツールB：改行の整理と残りの確認 |
| やってみたい | 学習アプリ：最初の試作 |
| これなんすか | 調べ：OpenMuse（個人用AIエージェント） |

### ポイント

- 頭の言葉は、プロジェクト名にそろえます。調べものは「調べ：」、環境まわりは「環境：」です
- Claudeは全件の最初の依頼を読み、それでも分からない約20件は、返事や最後のやりとりまで読んで決めていました

## 3. 並びは「日付で区切る・最近動いた順」にする

### なぜグループ分けをやめたか

最初はプロジェクト別のグループを作りました。ところが、グループの並びは固定されます。どのプロジェクトを最後に触ったかは、グループをまたぐと分かりません。

知りたかったのは「最後に触ったのはどれか」でした。そこで、日付で区切って最近動いた順に並べる表示に戻しました。題名の頭にプロジェクト名が付いているので、グループに分けなくてもどのプロジェクトかは読めます。

### 頼み方

```
> サイドバーを日付で区切って、最近動いた順に並べて
```

### ポイント

- 開いて見返しただけでは、並び順は変わりませんでした。並びは最後に作業した順です
- グループ自体は消さずに残しておけば、あとで切り替えられます

## 4. ピンは「今やるもの」、題名に「次＝」を入れる

### ピン留めとは

サイドバーの一番上に、常に出しておく印です。日付の区切りより上に出るので、上の欄が「今やるもの」、下の欄が「最近触ったもの」になります。

### 頼み方

```
> 優先のプロジェクトの最新セッションをピン留めして、題名に次の一手を入れて
```

### 付け直した例

```
アプリA：次＝閉じていても通知が届くか2台で試す
ハッカソンB：次＝Devpost登録とクレジット申込（10/31締切）
工作C：次＝はんだ練習10か所（10月末公開）
```

### ポイント

- 題名に「★」のような印を付ける案もありました。ただ、優先度は週ごとに変わるのに、題名は残ります。印はすぐ古くなります
- ピン留めしたセッションのひとつは、私の返事を待って止まっていました。Claudeが題名を付け直すために最後のやりとりを読んで、それが分かりました

## 5. 新しいセッションにはフックで効かせる

### なぜ「覚えさせる」ではだめか

放っておくと、新しいセッションの題名はまた最初の一言になります。

Claudeに覚えさせる（メモリに書く）方法もあります。ただ、私の環境では、Claude Code が自動で覚えたことは作業フォルダごとに分かれて保存されていました。別のフォルダで始めたセッションには効きません。

### フックとは

Claude Code に「このタイミングで毎回これを動かして」と登録しておく、小さなプログラムです。どのフォルダで始めても動きます。

今回使ったのは、依頼を送ったときに動く種類です。そこでClaudeへの指示を1文添えられます。

📎 詳しい仕組み: [Claude Code のフックの公式ドキュメント（英語）](https://code.claude.com/docs/en/hooks)

### 作ったフック

新しいセッションの最初の依頼で1回だけ、「題名を『プロジェクト名：中身』に付け直して」という指示を添えます。同じプロジェクトの別のセッションがピン留めされていれば、ピンを新しいほうへ移すことも頼みます。

GitHub で公開しました。

https://github.com/shoujiki-panman/claude-code-session-titles

![フックで題名が付け直されるまでの流れ](/images/claude-code-session-titles/hook-flow.png)
*新しいセッションの題名が付け直されるまで*

### 入れ方

デスクトップアプリの Code タブで、URLを渡して頼むだけです。

```
> https://github.com/shoujiki-panman/claude-code-session-titles これ設定しといて
```

説明書き（README）にClaude向けの手順を書いてあるので、Claudeがそれを読んで入れます。この書き方は、[claude-code-japanese-guard](https://github.com/minorun365/claude-code-japanese-guard) を参考にしました。

### 頭の言葉を決める

何も決めなければ、Claudeが作業しているプロジェクトの名前を頭に付けます。決まった呼び名でそろえたいときは、次の場所にファイルを作り、1行に1つずつ書きます。

`~/.claude/session-title-prefixes.txt`

```
家計簿アプリ
ブログ
調べ
環境
```

### ポイント

- 優先リストは別に持ちません。サイドバーで今付いているピンが、そのまま優先リストです
- 題名を変えるのはClaudeで、フックが添えるのは指示だけです。毎回必ず付け直すとは保証できません
- 題名とピンを変えられるのは、デスクトップアプリのClaudeだけです。ターミナル版ではフックは動きますが、何も起きません

新しいセッションで「セッションとプロジェクト整理テスト」とだけ打つと、題名が「環境：セッションとプロジェクト整理テスト」に変わりました。

![新しいセッションで題名が付け直された画面](/images/claude-code-session-titles/retitled-new-session.png)
*フックを入れたあとの新しいセッション。Claudeが題名を付け直し、ピンは該当なしで触っていない*

## 使い分けの目安

| 困っていること | やること |
|---|---|
| 題名で何のセッションか分からない | 2の頼み方で付け直す。以後はフック |
| 最後に触ったのがどれか分からない | 3の表示にする |
| 次に何をするか分からない | 4のピンと「次＝」 |
| セッションが多すぎて探せない | 1のアーカイブ |

## 宣伝：止まった会話の続きは session-relay で

セッションを整理すると、次に困るのは「止まった会話の続き」です。利用枠や会話の長さで止まったとき、新しいセッションで同じ話を最初から説明し直すのは手間がかかります。

session-relay は、新しいチャットに「続きから」と打つだけで、前の会話を引き継ぐ道具です。新しいAIが前の会話を自分で読みに行き、あなたが実際に打った言葉をそのまま受け取って、続きから始めます。引き継ぎ書は書きません。Claude Code と Codex の間でも移せます。

[前に記事を書いた](https://zenn.dev/shoujiki_panman/articles/session-relay-no-handoff)あと、9月の2回の更新で次のことができるようになりました。

| できるようになったこと | 中身 |
|---|---|
| 渡す側から印を付ける | 止まった会話の側で「次はこれ」と印を付けておくと、新しいセッションで「続きから」と言うだけでその会話が返る。利用枠で止まった会話からでも付けられる |
| 同じ画面のまま軽くする | ターミナル版では、会話を区切り直しても同じ画面のまま続きから始められる（デスクトップアプリでは使えない） |
| プロジェクトごとに選ぶ | 会話の一覧を、プロジェクトごとにまとめて出す |
| 会話を図にする | プロジェクトと会話の一覧を、メモアプリの Obsidian で開ける図にして書き出す |
| 引き継ぐ先のAIを選ぶ | 続きを渡すAIの種類（モデル）を指定できる |
| 止まったら自分で直す | 動かなくなったときに点検して、止まっている部分を起こし直す |

入れ方は、ターミナルで次の2行です。

```
npm install -g @shoujiki-panman/session-relay
relay install
```
